XML – data in tags

XML (eXtensible Markup Language) looks like HTML, but you invent the tags yourself. It is not for displaying a page but for storing and exchanging data. On this page you will write XML, check it, display it with CSS, validate it against a DTD, search it with XPath and transform it with XSLT – all right in the browser.

1What XML is and what it is used for

XML is a W3C recommendation from 1998. It is not a replacement for HTML – the two languages have different goals:

HTMLXML
purposedisplay data – how it lookscarry data – what it is
tagsfixed (p, h1…)invented by the author (<phone>)
errorsthe browser silently fixes thema single error = the document is invalid

Where you meet it: data exchange between different systems, RSS news feeds, Office formats (.docx and .xlsx are ZIP files full of XML), SVG images, configuration files, web services. For very large data or for JavaScript, JSON is more common today; XML doesn’t store images and other binary data well – it is just text.

A business card written in XML – the tags describe what each piece of data means:

<?xml version="1.0" encoding="UTF-8"?>
<BusinessCard>
  <name>Jane Novak</name>
  <phone type="mobile">(+421) 900 123 456</phone>
  <email>jana@example.com</email>
</BusinessCard>

Technologies around XML:

  • DTD and XML Schema – rules for which tags a document may contain
  • XPath – a “path” to data in the document
  • XSLT – turning XML into something else (HTML, text, other XML)
  • XQuery – a query language for XML (like SQL for a database)

2Syntax and the “well-formed” check

A document that follows all the writing rules is well-formed. Only such a document can be read by a program (a parser). Type into the editor – the check runs immediately. Or break the document on purpose with the buttons:

Rules

  • A document has exactly one root element that wraps everything else.
  • Every tag must be closed. You can write an empty element in short form: <photo /> instead of <photo></photo>.
  • Letter case matters: <Name> and <name> are two different tags.
  • Tags must not overlap: <b><i>…</i></b>, not <b><i>…</b></i>.
  • An attribute value is always in quotes and can’t be shortened: selected="selected", not just selected.
  • A tag name starts with a letter or _, followed by letters, digits, -, _, .. It must not start with the word xml (in any letter case) and must not contain a space.
  • The declaration <?xml version="1.0" encoding="UTF-8"?> is optional, but if it is there it must be at the very beginning – not even a space before it. Without encoding UTF-8 is assumed; standalone="yes" says that the document doesn’t depend on external files (e.g. a DTD).
  • Comment: <!-- note -->.

3Attributes, CDATA, instructions, entities and namespaces

Attribute or element?

Attributes are in the opening tag and are named by the same rules as elements. They suit extra information about a piece of data (the type of phone); put the data itself into elements – they can repeat and nest.

<phone type="mobile" primary="primary">(+421) 900 123 456</phone>
<phone type="home">(+421) 37 765 4321</phone>
<phone type="work">(+421) 37 641 2000</phone>

CDATA – text the parser doesn’t read

The parser skips the content between <![CDATA[ and ]]> – you don’t have to replace the characters < and & in it. Handy for code samples.

<example><![CDATA[
  if (a < b && c > d) { alert("<b>OK</b>"); }
]]></example>

Processing instruction

An instruction for the program that processes the XML: <?target instruction?>. The best known one attaches a stylesheet: <?xml-stylesheet type="text/css" href="card.css"?>.

Entities

Characters that have a meaning in XML are replaced by an entity in text. A numeric entity writes any character by its code. Custom entities (shortcuts for longer text) are defined in a DTD.

Namespaces

When we combine XML from two sources, the same names with different meanings can meet – <table> as an HTML table and <table> as a piece of furniture. We resolve the conflict with a prefix that we bind to a unique address (URI) with an xmlns: attribute:

<root xmlns:h="http://www.w3.org/TR/html4/"
      xmlns:f="https://example.com/furniture">
  <h:table><h:tr><h:td>Apples</h:td></h:tr></h:table>
  <f:table><f:name>Coffee table</f:name></f:table>
</root>

4XML and the DOM

When you rent a car you have never driven, you don’t panic – you have a model in your head of how a car is driven. In the same way the browser builds a model of every document (HTML and XML) – the DOM (Document Object Model): a tree of nodes that JavaScript can reach too. It is a W3C standard, independent of language and platform. The tree on the right is drawn from the editor in part 2:

element · attribute · text · comment

JavaScript works with an XML tree the same way as with HTML (JS 2). First we take the text apart with a parser:

const xmlText = document.getElementById("wfArea").value;
const doc = new DOMParser().parseFromString(xmlText, "application/xml");

const name = doc.querySelector("name").textContent;
console.log("Name: " + name);

doc.querySelectorAll("phone").forEach(phone => {
  console.log(phone.getAttribute("type") + ": " + phone.textContent);
});

5Displaying XML with CSS

XML contains no information about appearance; without a stylesheet the browser shows it as a tree or as one long text. CSS works the same as with HTML, but we have to set everything ourselves – even whether an element is block, inline or none (hidden). We attach a stylesheet to XML with the instruction <?xml-stylesheet type="text/css" href="card.css"?>.

card.xml
card.css
result in the browser
::before and ::after insert text from the content property before/after the content. attr(type) prints the value of an attribute – phone::before { content: attr(type) ": "; }.
Counters: counter-reset: n; on the parent, counter-increment: n; on the item, and content: counter(n) ". "; prints them.
Tables: display: table, table-row, table-cell turn any elements into a table. Attribute selector: phone[primary].

6DTD – rules for a document

If you want other people (or programs) to send XML in your structure, you have to tell them which elements and attributes it may contain and in what order. A simple way is a DTD (Document Type Definition); more powerful but more complex is XML Schema. A document that is well-formed and also meets the rules of the DTD is valid.

Elements: <!ELEMENT name content>

(#PCDATA)text only (Parsed Character Data – the text between the tags)
EMPTYan empty element, e.g. <photo />
ANYanything
(to, from, body)exactly these elements in this order
(house | flat)one of them
(#PCDATA | b)*mixed content – text and elements
a? b* c+? 0 or 1×, * 0 or more×, + 1 or more×

Attributes: <!ATTLIST element attribute type default>

CDATAany text
(mobile|home|work)one of the listed values
IDa unique identifier
#REQUIREDrequired
#IMPLIEDoptional
#FIXED "1.0"if present, it must have exactly this value
"OK"default value when the attribute is missing

A DTD can be right inside the document (<!DOCTYPE root [ … ]>) or in a separate file that several documents use: <!DOCTYPE pets SYSTEM "pets.dtd">.

7XPath – a path to the data

XPath writes a path to elements much like a path to a file in folders: /BusinessCard/name. It is the basis of XSLT and XQuery. / at the start = from the root, // = anywhere in the document, [1] = the first one (counting from 1!), @type = an attribute, […] = a condition (predicate). 8XSLT – turning XML into HTML

Unlike CSS, XSLT (eXtensible Stylesheet Language Transformations) is a whole language: it contains templates (<xsl:template match="…">) that are matched to elements by XPath and replaced by their output. It is itself written in XML. From one XML it can produce an HTML page, text, other XML (and with further tools even PDF). The process: XML document + XSLT document → XSLT processor → result document.

Note: from version 158 (November 2026) Chrome has switched off its built-in XSLT, and other browsers plan to do the same. An XML file with <?xml-stylesheet type="text/xsl" …?> opened directly in the browser may no longer be transformed. That is why this page loads a replacement library in that case (the xslt-polyfill, ~1.5 MB). Outside the browser XSLT keeps working as usual (Python, Java, PHP, online testers).
