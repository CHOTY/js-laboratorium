XML – dáta v značkách

XML (eXtensible Markup Language) vyzerá ako HTML, ale značky si vymýšľaš sám. Neslúži na zobrazenie stránky, ale na uloženie a výmenu dát. Na tejto stránke si XML napíšeš, skontroluješ, zobrazíš cez CSS, overíš podľa DTD, prehľadáš cez XPath a pretransformuješ cez XSLT – všetko priamo v prehliadači.

1Čo je XML a na čo sa používa

XML je odporúčanie organizácie W3C z roku 1998. Nie je náhradou HTML – oba jazyky majú iný cieľ:

HTMLXML
účelzobraziť dáta – ako vyzerajúniesť dáta – čo to je
značkypevne dané (p, h1…)vymýšľa autor (<phone>)
chybyprehliadač ich potichu opravíjediná chyba = dokument je neplatný

Kde ho stretneš: výmena dát medzi rôznymi systémami, RSS kanály noviniek, formáty Office (.docx a .xlsx sú ZIP plný XML), obrázky SVG, konfiguračné súbory, webové služby. Pre veľmi veľké dáta alebo pre JavaScript je dnes častejší JSON; obrázky a iné binárne dáta XML neuloží dobre, je to len text.

Vizitka zapísaná v XML – značky popisujú, čo ktorý údaj znamená:

<?xml version="1.0" encoding="UTF-8"?>
<BusinessCard>
  <name>Jana Nováková</name>
  <phone type="mobile">(+421) 900 123 456</phone>
  <email>jana@example.com</email>
</BusinessCard>

Technológie okolo XML:

  • DTD a XML Schema – pravidlá, aké značky smie dokument obsahovať
  • XPath – „cesta“ k údajom v dokumente
  • XSLT – premena XML na niečo iné (HTML, text, iné XML)
  • XQuery – dopytovací jazyk nad XML (ako SQL nad databázou)

2Syntax a kontrola „well-formed“

Dokument, ktorý dodržiava všetky pravidlá zápisu, je well-formed (správne utvorený). Iba taký vie program (parser) prečítať. Píš do editora – kontrola beží hneď. Alebo dokument schválne pokaz tlačidlami:

Pravidlá

  • Dokument má práve jeden koreňový prvok, ktorý obaľuje všetko ostatné.
  • Každá značka sa musí zatvoriť. Prázdny prvok môžeš zapísať skrátene: <photo /> namiesto <photo></photo>.
  • Záleží na veľkosti písmen: <Name> a <name> sú dve rôzne značky.
  • Značky sa nesmú prekrývať: <b><i>…</i></b>, nie <b><i>…</b></i>.
  • Hodnota atribútu je vždy v úvodzovkách a nedá sa skrátiť: selected="selected", nie len selected.
  • Názov značky začína písmenom alebo _, potom písmená, číslice, -, _, .. Nesmie začínať slovom xml (v žiadnej veľkosti písmen) a nesmie obsahovať medzeru.
  • Deklarácia <?xml version="1.0" encoding="UTF-8"?> nie je povinná, ale ak je, musí byť úplne na začiatku – ani medzera pred ňou. Bez encoding sa predpokladá UTF-8; standalone="yes" hovorí, že dokument nezávisí od externých súborov (napr. DTD).
  • Komentár: <!-- poznámka -->.

3Atribúty, CDATA, inštrukcie, entity a menné priestory

Atribút alebo prvok?

Atribúty sú v začiatočnej značke a pomenúvajú sa podľa rovnakých pravidiel ako prvky. Hodí sa na ne doplňujúca informácia o údaji (typ telefónu), samotné dáta dávaj radšej do prvkov – dajú sa opakovať a vnárať.

<phone type="mobile" primary="primary">(+421) 900 123 456</phone>
<phone type="home">(+421) 37 765 4321</phone>
<phone type="work">(+421) 37 641 2000</phone>

CDATA – text, ktorý parser nečíta

Obsah medzi <![CDATA[ a ]]> parser preskočí – znaky < a & v ňom nemusíš nahrádzať. Hodí sa na ukážky kódu.

<example><![CDATA[
  if (a < b && c > d) { alert("<b>OK</b>"); }
]]></example>

Inštrukcia pre spracovanie

Pokyn pre program, ktorý XML spracúva: <?cieľ inštrukcia?>. Najznámejšia pripája štýl: <?xml-stylesheet type="text/css" href="card.css"?>.

Entity

Znaky, ktoré majú v XML význam, sa v texte nahrádzajú entitou. Číselná entita zapíše ľubovoľný znak podľa kódu. Vlastné entity (skratky za dlhší text) sa definujú v DTD.

Menné priestory (namespaces)

Keď spojíme XML z dvoch zdrojov, môžu sa stretnúť rovnaké názvy s rôznym významom – <table> ako HTML tabuľka a <table> ako kus nábytku. Konflikt vyriešime predponou, ktorú atribútom xmlns: spojíme s jedinečnou adresou (URI):

<root xmlns:h="http://www.w3.org/TR/html4/"
      xmlns:f="https://example.com/furniture">
  <h:table><h:tr><h:td>Jablká</h:td></h:tr></h:table>
  <f:table><f:name>Konferenčný stolík</f:name></f:table>
</root>

4XML a DOM

Keď si požičiaš auto, ktoré si nikdy nešoféroval, nepanikáriš – v hlave máš model, ako sa auto ovláda. Prehliadač si podobne z každého dokumentu (HTML aj XML) postaví model – DOM (Document Object Model): strom uzlov, ku ktorému sa dostane aj JavaScript. Je to štandard W3C, nezávislý od jazyka a platformy. Strom vpravo sa kreslí z editora v časti 2:

prvok · atribút · text · komentár

S XML stromom pracuje JavaScript rovnako ako s HTML (JS 2). Najprv text rozoberieme parserom:

const xmlText = document.getElementById("wfArea").value;
const doc = new DOMParser().parseFromString(xmlText, "application/xml");

const name = doc.querySelector("name").textContent;
console.log("Meno: " + name);

doc.querySelectorAll("phone").forEach(phone => {
  console.log(phone.getAttribute("type") + ": " + phone.textContent);
});
Výstup sa zobrazí tu.

5Zobrazenie XML pomocou CSS

XML neobsahuje žiadne informácie o vzhľade, prehliadač ho bez štýlu ukáže ako strom alebo jeden dlhý text. CSS funguje rovnako ako pri HTML, len všetko musíme nastaviť my – aj to, či je prvok block, inline alebo none (skrytý). Štýl k XML pripojíme inštrukciou <?xml-stylesheet type="text/css" href="card.css"?>.

card.css
výsledok v prehliadači
::before a ::after vložia pred/za obsah text z vlastnosti content. attr(type) vypíše hodnotu atribútu – phone::before { content: attr(type) ": "; }.
Počítadlá: counter-reset: n; na rodičovi, counter-increment: n; na položke a content: counter(n) ". "; ich vypíše.
Tabuľky: display: table, table-row, table-cell spravia z ľubovoľných prvkov tabuľku. Selektor atribútu: phone[primary].

6DTD – pravidlá pre dokument

Ak chceš, aby iní ľudia (alebo programy) posielali XML v tvojej štruktúre, musíš im povedať, aké prvky a atribúty smie obsahovať a v akom poradí. Jednoduchý spôsob je DTD (Document Type Definition); mocnejšia, ale zložitejšia je XML Schema. Dokument, ktorý je well-formed a navyše spĺňa pravidlá DTD, je valid (platný).

Prvky: <!ELEMENT názov obsah>

(#PCDATA)iba text (Parsed Character Data – text medzi značkami)
EMPTYprázdny prvok, napr. <photo />
ANYčokoľvek
(to, from, body)presne tieto prvky v tomto poradí
(house | flat)jeden z nich
(#PCDATA | b)*zmiešaný obsah – text aj prvky
a? b* c+? 0 alebo 1×, * 0 a viac×, + 1 a viac×

Atribúty: <!ATTLIST prvok atribút typ predvolené>

CDATAľubovoľný text
(mobile|home|work)jedna z vymenovaných hodnôt
IDjedinečný identifikátor
#REQUIREDpovinný
#IMPLIEDnepovinný
#FIXED "1.0"ak je uvedený, musí mať presne túto hodnotu
"OK"predvolená hodnota, keď atribút chýba

DTD môže byť priamo v dokumente (<!DOCTYPE koreň [ … ]>) alebo v samostatnom súbore, ktorý použije viac dokumentov: <!DOCTYPE pets SYSTEM "pets.dtd">.

Validátor

Prehliadač DTD nekontroluje, preto sme mu pripísali malý validátor (zvláda ELEMENT a ATTLIST z vnútornej DTD). Pokaz dokument – vymaž <age>, prehoď poradie prvkov, zmeň type="mobile" na "fax"…

Na skutočné projekty: online validátory, napr. xmlvalidation.com.

7XPath – cesta k údajom

XPath zapisuje cestu k prvkom podobne ako cestu k súboru v priečinkoch: /BusinessCard/name. Je základom XSLT aj XQuery. / na začiatku = od koreňa, // = kdekoľvek v dokumente, [1] = prvý (číslujeme od 1!), @type = atribút, […] = podmienka (predikát). Klikni na výraz alebo napíš vlastný:

8XSLT – premena XML na HTML

XSLT (eXtensible Stylesheet Language Transformations) je na rozdiel od CSS celý jazyk: obsahuje šablóny (<xsl:template match="…">), ktoré sa priradia prvkom podľa XPath a nahradia ich výstupom. Sám je zapísaný v XML. Z jedného XML vie vyrobiť HTML stránku, text, iné XML (a s ďalšími nástrojmi aj PDF). Postup: XML dokument + XSLT dokument → XSLT procesor → výsledný dokument.

pets.xml
pets.xslt
Pozor: Chrome od verzie 158 (november 2026) zabudované XSLT vypol a ostatné prehliadače to plánujú tiež. Súbor XML s <?xml-stylesheet type="text/xsl" …?> otvorený priamo v prehliadači sa už nemusí premeniť. Táto stránka si preto v takom prípade sama načíta náhradnú knižnicu (polyfill xslt-polyfill, ~1,5 MB). Mimo prehliadača XSLT ďalej funguje bežne (Python, Java, PHP, online testery).
