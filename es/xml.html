XML – datos entre etiquetas

XML (eXtensible Markup Language) se parece a HTML, pero las etiquetas te las inventas tú. No sirve para mostrar una página, sino para guardar e intercambiar datos. En esta página escribirás XML, lo comprobarás, lo mostrarás con CSS, lo validarás con una DTD, lo recorrerás con XPath y lo transformarás con XSLT, todo directamente en el navegador.

1Qué es XML y para qué se usa

XML es una recomendación del W3C de 1998. No sustituye a HTML: los dos lenguajes tienen objetivos distintos:

HTMLXML
objetivomostrar datos – cómo se ventransportar datos – qué son
etiquetasfijas (p, h1…)las inventa el autor (<phone>)
erroresel navegador los corrige sin avisarun solo error = el documento no es válido

Dónde lo encontrarás: intercambio de datos entre sistemas distintos, canales de noticias RSS, formatos de Office (.docx y .xlsx son un ZIP lleno de XML), imágenes SVG, archivos de configuración, servicios web. Para datos muy grandes o para JavaScript hoy es más común JSON; XML no guarda bien las imágenes y otros datos binarios, es solo texto.

Una tarjeta de visita escrita en XML: las etiquetas describen qué significa cada dato:

<?xml version="1.0" encoding="UTF-8"?>
<BusinessCard>
  <name>Juana Novak</name>
  <phone type="mobile">(+421) 900 123 456</phone>
  <email>jana@example.com</email>
</BusinessCard>

Tecnologías en torno a XML:

  • DTD y XML Schema: reglas sobre qué etiquetas puede contener un documento
  • XPath: un “camino” hasta los datos del documento
  • XSLT: convertir XML en otra cosa (HTML, texto, otro XML)
  • XQuery: un lenguaje de consultas sobre XML (como SQL sobre una base de datos)

2Sintaxis y la comprobación “well-formed”

Un documento que cumple todas las reglas de escritura está bien formado (well-formed). Solo un documento así lo puede leer un programa (un parser). Escribe en el editor: la comprobación es inmediata. O estropea el documento a propósito con los botones:

Reglas

  • Un documento tiene exactamente un elemento raíz que envuelve todo lo demás.
  • Cada etiqueta debe cerrarse. Un elemento vacío se puede escribir abreviado: <photo /> en lugar de <photo></photo>.
  • Importan las mayúsculas y minúsculas: <Name> y <name> son dos etiquetas distintas.
  • Las etiquetas no pueden cruzarse: <b><i>…</i></b>, no <b><i>…</b></i>.
  • El valor de un atributo siempre va entre comillas y no se puede abreviar: selected="selected", no solo selected.
  • El nombre de una etiqueta empieza por una letra o _, seguido de letras, dígitos, -, _, .. No puede empezar por la palabra xml (en ninguna combinación de mayúsculas) ni contener espacios.
  • La declaración <?xml version="1.0" encoding="UTF-8"?> no es obligatoria, pero si está, debe ir al principio del todo, sin ni siquiera un espacio delante. Sin encoding se supone UTF-8; standalone="yes" indica que el documento no depende de archivos externos (p. ej. una DTD).
  • Comentario: <!-- nota -->.

3Atributos, CDATA, instrucciones, entidades y espacios de nombres

¿Atributo o elemento?

Los atributos van en la etiqueta de apertura y se nombran con las mismas reglas que los elementos. Sirven para información adicional sobre un dato (el tipo de teléfono); los datos en sí mejor ponlos en elementos: se pueden repetir y anidar.

<phone type="mobile" primary="primary">(+421) 900 123 456</phone>
<phone type="home">(+421) 37 765 4321</phone>
<phone type="work">(+421) 37 641 2000</phone>

CDATA – texto que el parser no lee

El parser se salta el contenido entre <![CDATA[ y ]]>: dentro no tienes que sustituir los caracteres < y &. Muy útil para ejemplos de código.

<example><![CDATA[
  if (a < b && c > d) { alert("<b>OK</b>"); }
]]></example>

Instrucción de procesamiento

Una orden para el programa que procesa el XML: <?destino instrucción?>. La más conocida enlaza una hoja de estilos: <?xml-stylesheet type="text/css" href="card.css"?>.

Entidades

Los caracteres que tienen un significado en XML se sustituyen en el texto por una entidad. Una entidad numérica escribe cualquier carácter por su código. Las entidades propias (abreviaturas de un texto más largo) se definen en una DTD.

CarácterEntidadNumérica

<!DOCTYPE card [
  <!ENTITY company "Stann &amp; White &#174;">
]>
<card><company>&company;</company></card>

Espacios de nombres (namespaces)

Cuando juntamos XML de dos fuentes, pueden coincidir nombres iguales con significados distintos: <table> como tabla de HTML y <table> como mueble. El conflicto se resuelve con un prefijo que unimos a una dirección única (URI) con el atributo xmlns::

<root xmlns:h="http://www.w3.org/TR/html4/"
      xmlns:f="https://example.com/furniture">
  <h:table><h:tr><h:td>Manzanas</h:td></h:tr></h:table>
  <f:table><f:name>Mesa de centro</f:name></f:table>
</root>

4XML y el DOM

Cuando alquilas un coche que nunca has conducido, no te asustas: tienes en la cabeza un modelo de cómo se conduce un coche. Igualmente, el navegador construye un modelo de cada documento (HTML y XML): el DOM (Document Object Model), un árbol de nodos al que también llega JavaScript. Es un estándar del W3C, independiente del lenguaje y de la plataforma. El árbol de la derecha se dibuja a partir del editor de la parte 2:

elemento · atributo · texto · comentario

JavaScript trabaja con un árbol XML igual que con HTML (JS 2). Primero descomponemos el texto con un parser:

const xmlText = document.getElementById("wfArea").value;
const doc = new DOMParser().parseFromString(xmlText, "application/xml");

const name = doc.querySelector("name").textContent;
console.log("Nombre: " + name);

doc.querySelectorAll("phone").forEach(phone => {
  console.log(phone.getAttribute("type") + ": " + phone.textContent);
});

5Mostrar XML con CSS

XML no contiene ninguna información sobre el aspecto; sin hoja de estilos el navegador lo muestra como un árbol o como un texto largo. CSS funciona igual que con HTML, pero tenemos que definirlo todo nosotros, incluso si un elemento es block, inline o none (oculto). La hoja de estilos se enlaza al XML con la instrucción <?xml-stylesheet type="text/css" href="card.css"?>.

card.xml
card.css
resultado en el navegador
::before y ::after insertan antes/después del contenido el texto de la propiedad content. attr(type) muestra el valor de un atributo: phone::before { content: attr(type) ": "; }.
Contadores: counter-reset: n; en el padre, counter-increment: n; en cada elemento y content: counter(n) ". "; los muestra.
Tablas: display: table, table-row, table-cell convierten cualquier elemento en una tabla. Selector de atributo: phone[primary].

6DTD – reglas para un documento

Si quieres que otras personas (o programas) envíen XML con tu estructura, tienes que decirles qué elementos y atributos puede contener y en qué orden. Una forma sencilla es una DTD (Document Type Definition); más potente pero más compleja es XML Schema. Un documento bien formado que además cumple las reglas de la DTD es válido (valid).

Elementos: <!ELEMENT nombre contenido>

(#PCDATA)solo texto (Parsed Character Data: el texto entre las etiquetas)
EMPTYun elemento vacío, p. ej. <photo />
ANYcualquier cosa
(to, from, body)exactamente estos elementos en este orden
(house | flat)uno de ellos
(#PCDATA | b)*contenido mixto: texto y elementos
a? b* c+? 0 o 1 vez, * 0 o más veces, + 1 o más veces

Atributos: <!ATTLIST elemento atributo tipo predeterminado>

CDATAcualquier texto
(mobile|home|work)uno de los valores enumerados
IDun identificador único
#REQUIREDobligatorio
#IMPLIEDopcional
#FIXED "1.0"si aparece, debe tener exactamente este valor
"OK"valor por defecto cuando falta el atributo

Una DTD puede ir dentro del documento (<!DOCTYPE raíz [ … ]>) o en un archivo aparte que usen varios documentos: <!DOCTYPE pets SYSTEM "pets.dtd">.

Validador

El navegador no comprueba las DTD, así que le hemos escrito un pequeño validador (entiende ELEMENT y ATTLIST de la DTD interna). Estropea el documento: borra <age>, cambia el orden de los elementos, cambia type="mobile" por "fax"…

Para proyectos reales: validadores en línea, p. ej. xmlvalidation.com.

7XPath – un camino hasta los datos

XPath escribe el camino hasta los elementos de forma parecida a la ruta de un archivo en carpetas: /BusinessCard/name. Es la base de XSLT y XQuery. / al principio = desde la raíz, // = en cualquier parte del documento, [1] = el primero (¡se cuenta desde 1!), @type = un atributo, […] = una condición (predicado). 8XSLT – convertir XML en HTML

A diferencia de CSS, XSLT (eXtensible Stylesheet Language Transformations) es todo un lenguaje: contiene plantillas (<xsl:template match="…">) que se asignan a los elementos mediante XPath y los sustituyen por su resultado. Está escrito en XML. A partir de un XML puede generar una página HTML, texto, otro XML (y con más herramientas, incluso PDF). El proceso: documento XML + documento XSLT → procesador XSLT → documento resultante.

pets.xslt
Atención: desde la versión 158 (noviembre de 2026) Chrome ha desactivado su XSLT integrado y los demás navegadores planean hacer lo mismo. Un archivo XML con <?xml-stylesheet type="text/xsl" …?> abierto directamente en el navegador puede que ya no se transforme. Por eso esta página carga en ese caso una biblioteca de sustitución (el xslt-polyfill, ~1,5 MB). Fuera del navegador XSLT sigue funcionando con normalidad (Python, Java, PHP, probadores en línea).
